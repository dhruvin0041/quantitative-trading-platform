# SECURITY HARDENING

Hydra Terminal is engineered with institutional-grade security protocols to protect sensitive quantitative models and financial data.

## 1. API Security
- **API Key Verification**: All endpoints are protected by a mandatory `X-API-Key` header. Requests with invalid or missing keys are immediately rejected with a `403 Forbidden` status.
- **Rate Limiting**: Integrated middleware enforces IP-based rate limiting (default: 50 requests per minute) to prevent brute-force attacks and resource exhaustion.
- **RESTful Sanitization**: Ticker symbols and query parameters undergo strict regex-based sanitization to prevent injection and path traversal attempts.

## 2. Network & CORS
- **Restricted Origins**: The system implements a strict Cross-Origin Resource Sharing (CORS) policy. Only pre-configured frontend URLs (defined in `.env`) are permitted to interact with the backend API.
- **Unified Configuration**: Secure environment variables are managed via Pydantic/Dotenv, ensuring secrets like `API_KEY` and `GOOGLE_API_KEY` are never exposed in logs or source control.

## 3. Data Integrity & "Zero-State"
- **Memory Protection**: The "Zero-State" protocol (`clean_artifacts.py`) systematically wipes local model weights and scalers when switching research contexts, preventing cross-ticker neural pathway contamination.
- **Validation Gates**: Every signal generated by the Alpha Agent must pass through a Risk Agent "Veto" layer before being logged or presented to the UI.

## 4. Operational Best Practices
- **Production Logs**: Structured JSON logging is used to ensure all security events (e.g., unauthorized access attempts) are audit-ready and observable.
- **Minimal Surface Area**: The system uses multi-stage Docker builds to ensure the production image contains only the necessary runtimes, reducing the attack surface.
- **Dependency Isolation**: All core packages are pinned in `requirements.txt` and validated via automated CI linting (Ruff).
